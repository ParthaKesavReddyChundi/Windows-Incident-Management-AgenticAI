# Windows Disk I/O & Storage Anomaly Troubleshooting Guide

## Category: Disk Bottlenecks & Storage Degradation
**Source:** Windows Systems Administration & SRE Runbooks  
**Tags:** disk, io, storage, queue_length, throughput, chkdsk, vss, search_indexer

---

### Section: Disk Queue Length & Bottlenecks Overview
Disk performance degradation occurs when storage subsystem throughput and IOPS (Input/Output Operations Per Second) capacity are saturated by aggressive disk read/write requests, causing request queueing, application hangs, and severe system latency.

#### Common Symptoms
- Total disk active time reaches 100% on system or data drives.
- High average disk queue length (> 2.0 per physical disk spindle).
- High disk read/write latency (> 25 ms for SSDs, > 50 ms for HDDs).
- File operations become unresponsive, and Event ID 129 (`Reset to device, \Device\RaidPort0, was issued`) appears in the System event log.

#### Key Performance Metrics
- `disk_read_bytes_per_sec`: Current read transfer rate in bytes per second.
- `disk_write_bytes_per_sec`: Current write transfer rate in bytes per second.
- `PhysicalDisk: % Disk Time`: Percentage of elapsed time that the selected disk drive was busy servicing read or write requests.
- `PhysicalDisk: Avg. Disk Queue Length`: Average number of both read and write requests queued for the selected disk.

### Section: Runaway Disk Thrashing
Excessive un-throttled writes or random reads generated by background processes, un-indexed database queries, log runaway, or rogue software.

#### Root Causes
- Windows Search Indexer (`SearchIndexer.exe`) stuck rebuilding catalog over network shares or massive file repositories.
- Windows Update delivery optimization or background installation (`TiWorker.exe`, `TrustedInstaller.exe`).
- Logging runaway: An application repeatedly emitting stack traces or debug logs into a text file at hundreds of megabytes per minute.
- Backup, antivirus full disk scan, or Volume Shadow Copy (VSS) snapshot synchronization running during business hours.

#### Diagnostic Procedure
1. Inspect `disk_collector` telemetry for sudden spikes in read/write throughput (e.g. > 150 MB/s).
2. Use Resource Monitor or PowerShell to identify top disk I/O processes:
   `Get-Process | Sort-Object -Property ReadOperationCount, WriteOperationCount -Descending | Select-Object -First 5 Name, Id, ReadOperationCount, WriteOperationCount`.
3. Check drive free space: Partition space below 10% severely impairs file system defragmentation and temporary allocation.
4. Review Event Viewer `System` log for NTFS errors (Event ID 55, 98, or 130).

#### Remediation Actions
1. **Throttle Windows Search Indexer (Low Risk):** Temporarily pause or lower indexing priority:
   `Stop-Service WSearch` or modify indexing backoff policy.
2. **Purge Temporary & Log Storage (Low Risk):** Safely clean `%SystemRoot%\Temp` and `%LocalAppData%\Temp` to restore free block headroom.
3. **Throttle Heavy I/O Process Priority (Medium Risk):** Lower the process I/O priority to `Very Low` using `wmic process where processid=<PID> call setpriority 64` or process utilities.
4. **Reschedule Resource-Intensive Scans (Low Risk):** Ensure Windows Defender full disk scans and VSS backups are configured to run during low-traffic maintenance windows.
5. **Run Storage Health Check (Read-Only):** Execute `chkdsk C: /scan` in read-only online mode to verify file system structural integrity.
